Talk

Tell me how you review a fix. A conversation, before anything ships.

Tracefix is for people who review bug fixes that a coding agent wrote. Before it is released, I want to learn how you review them today: what you check, what you trust, and what has slipped past. It takes about twenty minutes, on a call or by email, whichever suits you.

Email founder@tracefix.dev What I would ask

Private preview: Tracefix is not released yet, so there is nothing to install and its GitHub links open only for collaborators.

What I would ask. No pitch, and a demo only if you want one.

About your reviews

  • How you decide that a fix from an agent is right before you merge it.
  • The last fix that looked right and was not: what caught it, or what would have.
  • What you run beyond the pull request’s own tests, if anything.

About a receipt

  • What a receipt would have to show before you trusted it, and what would make you ignore it.
  • Whether a false alarm costs you more than a missed bug.
  • Where it would run: in CI on every pull request, by hand, or nowhere.

What to expect. Your time, not your code.

  • A conversation only. I will not ask for your code or run anything on it.
  • What you tell me stays in my notes. Nothing you say goes on this site, or anywhere public, unless you agree first.
  • If you want, you hear when Tracefix is released. Nothing else lands in your inbox.

Why it matters

Release gate 7, “Someone wants it”, counts these conversations: 0 so far, against a target of ≥ 5, notes kept. Tracefix is released only when all 7 gates hold; today 0 do.
